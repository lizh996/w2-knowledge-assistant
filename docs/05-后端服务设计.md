# 后端服务设计

> **文档来源**：实现过程中定稿（api.py/pipeline.py，踩坑后修复）


> 后端进程如何组织、任务如何管理、并发如何保证、权限如何控制。

## 一、进程模型

```
uvicorn 单进程（FastAPI, 端口 8011）
├── 主线程：接收请求（问答秒级响应）
└── ThreadPoolExecutor 后台线程池：跑上传构建（慢活不阻塞快活）
```

```
问答请求 → 主线程直接处理（检索+生成 ≈ 几秒）
上传请求 → 丢线程池（六步构建几分钟），主线程秒回 task_id
```

## 二、任务状态机（SQLite 持久化）

```
pending → parsing → cleaning → chunking → vectorizing → upserting → done
                                   └──────────────→ failed（任一步异常）

状态存 data/pipeline_tasks.sqlite：
  task_id / filename / status / steps(JSON) / error / created_at / updated_at

每步完成 → UPDATE steps 里对应 state=done + 耗时
刷新页面/服务重启 → SELECT 读回 → 进度不丢（_recover_interrupted_tasks 恢复中断任务）
```

## 三、并发安全（踩坑修复）

| 坑 | 问题 | 修复 |
|---|---|---|
| 模型并发加载 | 3 个任务同时 vectorize → 各加载 2GB BGE-M3 → meta tensor 崩溃 | `_get_model()` 单例 + `_VECTORIZE_LOCK` 串行 |
| Qdrant 单进程锁 | 评测脚本和服务同时开库 → "already accessed" | 评测前停 uvicorn；服务独占 qdrant |

## 四、鉴权

```
POST /login → {token, role}（默认 admin/admin123）
所有业务接口带 Authorization: Bearer <token>
401 未登录 / 403 权限不足（内置文档不可删）
token 有有效期，服务重启后前端自动失效需重登
```

## 五、评测历史

```
data/eval_history.sqlite：记录历次评测（版本/recall@5/MRR/拒答率）
后台「评测趋势」页读取 → 画曲线
```

## 六、可观测

```
trace 8 步：question_input→reject→dense→sparse→rrf→rerank→organize→generation→citation
/api/ask 返回 trace.steps（每步 state/elapsed_ms）
检索测试台：/retrieve-test 四路独立查看（dense/sparse/rrf/reranked）
系统健康：/admin/health 三查（qdrant/生成/精排）
```
