## 一、项目背景

某供电公司变电运维班组日常检修变压器，需要频繁查阅国标条款：
- 变压器油该做哪些气相色谱检测？（GB/T 17623）
- 变压器技术参数有什么要求？（GB/T 25438）
- 专用设备怎么检测验收？（GB/T 27743）

**痛点**：
1. 标准纸质版/电子版分散，现场查找慢
2. 指标值多（气体含量限值、温度、压力等），凭记忆易出错
3. 网上问大模型没有依据、可能编造，运维操作不敢信

## 二、用户画像

| 维度 | 描述 |
|---|---|
| 主要用户 | 电力公司变电运维人员（检修班组）|
| 使用场景 | 现场检修 / 培训学习 / 标准核对 |
| 核心诉求 | 快速查标准条款 + 要准确（带页码出处）|
| 技术水平 | 会用浏览器，不要求懂技术 |

## 三、功能清单（用户视角）

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 文档上传 | 拖拽上传国标 PDF，自动构建知识库 | 高 |
| F2 | 标准问答 | 提问 → 答案 + 页码出处 | 高 |
| F3 | 引用溯源 | 每条答案标注 [标准 · 第 X 页] | 高 |
| F4 | 无依据拒答 | 库外问题明确说"知识库依据不足"，不编造 | 高 |
| F5 | 多文档检索 | 问题跨 3 份标准检索融合 | 高 |
| F6 | 多轮对话 | 追问"那它的检测流程呢"能接上下文 | 中 |
| F7 | 检索过程可见 | 展示检索链路（哪路命中/耗时/分数）| 中 |
| F8 | 知识库管理 | 查看块/向量库/检索测试（后台）| 中 |

## 四、非功能需求

| # | 需求 | 说明 |
|---|---|---|
| NFR1 | 可溯源 | 答案必须带页码，无依据不答 |
| NFR2 | 可评测 | recall@k / MRR / faithfulness 指标可量化 |
| NFR3 | 可复现 | 同文档重复构建结果一致 |
| NFR4 | 原子性 | 构建失败不产生半成品知识库 |
| NFR5 | 响应 | 问答 ≤ 10 秒（不含解析构建）|

## 五、范围边界

**范围内**：3 份内置国标 + 上传新 PDF；文本/表格/公式/图解析问答；本机部署

**范围外（后续版本）**：多租户/移动端/嵌入模型微调/其他语种

## 六、技术选型（头脑风暴产出）

| 环节 | 选型 | 为什么 |
|---|---|---|
| 解析 | fitz + MinerU 双通道 | 正常 PDF 秒级，乱码/扫描兜底 |
| 嵌入 | BGE-M3 | dense+sparse 双向量，本地零成本 |
| 向量库 | Qdrant embedded | 双向量 + FusionQuery RRF，免运维 |
| 生成 | DeepSeek-V4-Flash | 中文好、便宜、支持带页码引用 |
| 服务 | FastAPI | 多接口自动文档，开发快 |
| 前端 | 原生 HTML/JS | 零构建，ECharts/KaTeX 本地化 |

## 七、迭代规划（V1→V2→V3）

| 版本 | 定位 | 核心内容 |
|---|---|---|
| V1 | MVP 基线 | 解析+分块+向量化+朴素检索+问答带页码溯源；建评测集+基线 |
| V2 | 增强 | trace（检索链路可视化）+ 复杂元素提取 + 复合检索 |
