# 数据管线设计

> **文档来源**：实现过程中定稿（pipeline.py 六步 + 实测 88 块）


> 上传一份 PDF 到"能回答问题"，中间经过六步构建（pipeline.py 实现）。

## 一、管线六步

```
① 解析  ② 清洗  ③ 分块  ④ 向量化  ⑤ 入库  ⑥ 自检
parse → clean → chunk → vectorize → upsert → selfcheck
```

| 步骤 | 做什么 | 关键实现 |
|---|---|---|
| ① 解析 parse | 读 PDF 出文本/页 | fitz 秒级；乱码/扫描切 MinerU GPU（`_mineru_parse`）|
| ② 清洗 clean | 去乱码/修复文本 | 乱码检测（`_looks_garbled`）+ 规则修复 |
| ③ 分块 chunk | 切成 512 token 块 | 按章节切（`build_chunks`），语义类型分类 |
| ④ 向量化 vectorize | 每块转 dense+sparse | BGE-M3 单例 + 加锁（`_VECTORIZE_LOCK`）|
| ⑤ 入库 upsert | 写 Qdrant 独立集合 | 每份文档一个 `transformer_upload_*` 集合 |
| ⑥ 自检 selfcheck | 验证可检索 | 抽样检索自检（`self_check`）|

## 二、各步骤实现要点

### 解析双通道（fitz / MinerU）
```
正常 PDF（文字可提取）→ fitz 秒级（extract.py）
乱码/扫描版 → MinerU GPU 视觉识别版面 → 转文字（带图）
判定：`_looks_garbled()` 检测乱码 + 页数阈值兜底
```

### 分块策略
```
按章节切分（chunker.py `chunk_by_section`）
512 token 上限（`_split_by_tokens`）
语义类型分类：概述/术语定义/参数查询/流程步骤/标准要求/安全要求/图语义
每个块生成：页码 / source / important_kwd / question_kwd（供检索/评测用）
```

### 向量化（BGE-M3 dense + sparse）
```
复用 retrieve._get_model() 单例（禁止多任务并发加载 2GB 模型——踩坑修复）
加 _VECTORIZE_LOCK 串行化
每块输出：dense(1024维, 余弦) + sparse(词权重 IDF)
```

## 三、中间产物

| 产物 | 路径 | 内容 |
|---|---|---|
| 解析页 | 内存 | {page, text, type} |
| 分块结果 | Qdrant payload | 块文本 + page/source/semantic_type/kwd |
| 任务记录 | data/pipeline_tasks.sqlite | 每步状态/耗时/统计 |
| 上传文件 | data/uploads/ | 原始 PDF |
