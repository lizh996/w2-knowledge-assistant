# M5 版本迭代文档（V1 → V2 → V3）

## 一、版本总览

| 版本 | 定位 | 改了什么 | 为什么改 | 指标 |
|---|---|---|---|---|
| V1 | MVP 基线 | 解析+分块+向量化+朴素检索+问答溯源 | 先跑通、先立"尺子" | recall 0.9167 / MRR 0.6625 |
| V2 | 增强 | trace 可观测 + 复杂元素提取 + 复合检索 + 运维控制台 | 先能看检索详情/归因；补表/图/公式语义 | 复杂元素题 2/3 命中；可观测性 |
| V3 | 进阶 | reranker 精排 + 查询改写 + 上下文组织 | 多文档噪声大需精排；口语 query 需改写 | **MRR 0.6625→0.6694** |

## 二、V1 迭代记录（MVP）

**做了什么**：3 份国标（17623/25438/27743）→ fitz 解析 → 结构分块（≤512 token）→ BGE-M3 向量化（dense+sparse）→ Qdrant 入库 → FastAPI /ask 问答 → 前端。

**遇到的问题**：
1. **并发向量化 meta tensor 崩溃**：3 个上传任务同时触发模型加载，多实例冲突。
   **解决**：`vectorize_chunks` 复用 retrieve 模型单例 + 加锁（`_VECTORIZE_LOCK`）。
2. **Qdrant 单进程锁**：服务运行时评测脚本连不上。
   **解决**：评测前停服务，跑完再启动。

**验证**：检索集 12 题 recall@5=0.9167、MRR=0.6625；拒答 10 题 100%。

## 三、V2 迭代记录（增强）

**做了什么**：
1. **trace 可观测**：/ask 返回 8-10 步链路（问题输入→拒答判断→Dense/Sparse→RRF→精排→上下文组织→生成→引用），每步耗时。
2. **复杂元素提取**：表=整表原子块（不拆行级碎块）；图=图语义块（标引序号展开+image_path）；公式=LaTeX 保留。
3. **复合检索**：dense+sparse 双向量 → Qdrant FusionQuery(RRF, k=60) 融合。
4. **运维控制台**：向量库浏览/检索测试台（四路分数）/文档管理。

**为什么**：任务书 V2 定义"引入 trace（先能看详情/归因）+ 复杂元素提取 + 复合检索"。trace 是后续优化的地基——**没有它，V3 精排/改写的效果无法归因**。

**遇到的问题**：检索测试台 reranked 通道是假的（只复制 RRF 分没跑模型）。**解决**：补真 reranker 调用。

## 四、V3 迭代记录（进阶）

**做了什么**：
1. **reranker 精排**：粗排 15 条 → bge-reranker-v2-m3 cross-encoder 逐条打分 → 取 5 条进 LLM。RERANK_ENABLED 开关。
2. **查询改写**：LLM 把口语 query 改写成规范术语（"气体咋规定的"→"气体纯度规定"），QUERY_REWRITE_ENABLED 开关+缓存+兜底。
3. **上下文组织**：生成前 score 阈值过滤（<0 丢弃）+ embedding 去重（余弦>0.90 合并）+ token 预算（≤2000）+ MIN_KEEP=2 兜底。
4. **citations 诚实化**：引用只列实际进 LLM 的块（不是搜索结果全部）。

**为什么**：任务书 V3 定义"+reranker 精排 + 查询改写 + trace 增强"。多文档（85 块）噪声大，精排能把真答案从 rank10 救回 rank1；口语 query 与 chunk 术语不匹配，改写对齐 Q2Q 索引侧。

**验证**：MRR 0.6625→0.6694（#4 题"重复性要求"从漏检→rank2 救回）。召回持平。

# 优化指标对比文档

## 版本对比表

| 版本 | recall@5 | MRR | 拒答准确率 | 说明 |
|---|---|---|---|---|
| V1 基线 | 0.9167 | 0.6625 | 100% | 朴素检索 |
| V2 增强 | 0.9167 | 0.6625 | 100% | +trace/复杂元素/复合检索（可观测性提升，检索算法未变）|
| V3 进阶 | 0.9167 | **0.6694** | 100% | +精排/改写/上下文组织 |

**MRR 提升归因**：
- **精排**：粗排 15 条时真答案可能排 rank7+，cross-encoder 精排把它救回前 5（#4"重复性要求"从漏检→rank2）
- **查询改写**：口语问题（"气体咋规定的"）改写为术语后，与 chunk 的 question_kwd 对齐，dense/sparse 命中更准
- **上下文组织**：过滤负分噪音块，进 LLM 的证据更干净 → 生成质量（faithfulness）提升

**仍弱项**：公式类题目（色谱计算公式）检索命中率低——复杂元素（公式）的语义化编码还需优化（列入后续版本）。
